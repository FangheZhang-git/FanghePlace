# Cookie sessions and CSP release

Authentication uses opaque random 256-bit session identifiers, not browser-readable JWTs. Production cookies are host-only `__Host-scholarmatch_session`, HttpOnly, Secure, SameSite=Lax, Path=/ and expire after one hour. Only a SHA-256 hash of the identifier is stored in MySQL. Every authenticated request joins the current users row so admin permissions are not cached in a token. Logout deletes the session row; expiry is enforced server-side. The new additive web_sessions table is initialized before listening and has a users foreign key and expiry index. Its user_id type follows the actual users.id column. The SQL migration targets the repository's BIGINT schema.

All browser authentication references move from localStorage to GET /api/session. Old token/user_id/username values are removed. All writes, including login and logout, require a cookie-bound HMAC CSRF token; cross-origin browser writes are rejected. Old bearer tokens are not accepted. Existing users must log in again after deployment. Keep JWT_SECRET configured: it now signs CSRF tokens, not login tokens. Do not print it.

The enforced CSP blocks inline JavaScript event handlers, eval, objects, foreign base URLs, foreign form submissions and framing. Inline JSON-LD uses startup-computed hashes. Existing inline CSS remains allowed; script unsafe-inline/unsafe-eval are not allowed. Explicit provider origins permit Turnstile and Google Translate. CSP violations are logged as directive and blocked origin only, through a bounded reporting endpoint. The language modal CSS collision is corrected and inline UI handlers are replaced with addEventListener.

Crawler-only @crawlee/core overrides minimatch to patched 11.0.1 (GHSA-g3hv-75wg-m249). Tests cover Crawlee's Minimatch and minimatch APIs, full crawler tests and dry-run. Both full and production npm audit report zero known vulnerabilities at validation time. Remove the override once upstream adopts a fixed compatible dependency.
